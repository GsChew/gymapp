# API проекта

Базовый URL при локальном запуске:

```text
http://127.0.0.1:8000
```

Интерактивная OpenAPI-документация доступна по адресу:

```text
http://127.0.0.1:8000/docs
```

Защищенные endpoint'ы используют Bearer token:

```http
Authorization: Bearer <access_token>
```

## Служебные endpoint'ы

### `GET /health`

Проверяет, что приложение отвечает.

Ожидаемый успешный ответ:

```json
{"status": "ok"}
```

### `GET /`

Возвращает статический frontend.

## Auth

### `POST /auth/register`

Регистрирует пользователя.

Типовой сценарий:

```json
{
  "username": "ivan",
  "password": "strong-password"
}
```

### `POST /auth/login`

Проверяет логин/пароль и возвращает access/refresh токены.

### `POST /auth/refresh`

Принимает refresh token и возвращает новую пару токенов.

### `GET /auth/me`

Возвращает текущего пользователя. Требует access token.

## Users

### `GET /users/`

Возвращает список пользователей. Доступно ролям с административными правами.

### `PATCH /users/{user_id}/role`

Меняет роль пользователя. Используется для управления доступом.

## Workouts

### `POST /workouts/starter-plan`

Создает стартовый план тренировок для нового пользователя. Сценарий должен быть
идемпотентным: повторный вызов не должен создавать дубли одного и того же плана.

### `GET /workouts/`

Возвращает тренировки текущего пользователя. Поддерживает фильтрацию и пагинацию.

### `GET /workouts/by-name/{workout_name}`

Ищет тренировку текущего пользователя по названию.

### `GET /workouts/{workout_id}`

Возвращает тренировку по id с проверкой владельца.

### `POST /workouts/`

Создает тренировку.

### `PATCH /workouts/{workout_id}`

Обновляет тренировку.

### `POST /workouts/{workout_id}/complete`

Отмечает тренировку выполненной и сохраняет wellness-поля, например самочувствие
и субъективную сложность. Для числовых wellness-полей используются границы `1..5`.

### `DELETE /workouts/{workout_id}`

Удаляет тренировку текущего пользователя.

## Workout exercises

### `POST /workout-exercises/`

Добавляет упражнение в тренировку.

### `GET /workout-exercises/`

Возвращает упражнения в тренировках пользователя.

### `GET /workout-exercises/status/{status}`

Фильтрует связи workout-exercise по статусу.

### `GET /workout-exercises/{workout_id}/{exercise_id}`

Возвращает конкретную связь тренировки и упражнения.

### `PATCH /workout-exercises/{workout_id}/{exercise_id}`

Обновляет подходы, повторения, вес, статус или другие поля связи.

### `DELETE /workout-exercises/{workout_id}/{exercise_id}`

Удаляет упражнение из тренировки.

## Exercises

### `GET /exercises/`

Возвращает каталог упражнений. Используется frontend-конструктором тренировок.

### `GET /exercises/{id}`

Возвращает упражнение по id.

### `POST /exercises/`

Создает упражнение. Доступно тренеру или администратору.

### `PATCH /exercises/{id}`

Обновляет упражнение. Доступно тренеру или администратору.

### `DELETE /exercises/{id}`

Удаляет упражнение. Доступно тренеру или администратору.

## Goals

### `GET /goals/`

Возвращает цели текущего пользователя.

### `POST /goals/`

Создает цель. Пример: целевой вес, недельное число тренировок или объем.

### `PATCH /goals/{goal_id}`

Обновляет цель. Пустое обновление считается ошибкой валидации бизнес-логики.

### `DELETE /goals/{goal_id}`

Удаляет цель текущего пользователя.

## Templates

### `GET /templates/`

Возвращает шаблоны тренировок пользователя.

### `POST /templates/`

Создает шаблон тренировки.

### `POST /templates/{template_id}/workouts`

Создает тренировку из шаблона и переносит упражнения шаблона в новую тренировку.

### `DELETE /templates/{template_id}`

Удаляет шаблон.

## Progress

### `GET /progress/summary`

Возвращает общую сводку прогресса: количество выполненных тренировок, объем и
другие агрегаты.

### `GET /progress/weekly-volume`

Возвращает недельный тренировочный объем.

### `GET /progress/exercises/{exercise_id}`

Возвращает рекорд по упражнению.

### `GET /progress/exercises/{exercise_id}/history`

Возвращает историю выполнения упражнения.

## Notifications

### `GET /notifications`

Возвращает уведомления текущего пользователя.

### `GET /notifications/unread-count`

Возвращает количество непрочитанных уведомлений.

### `GET /notifications/{id}`

Возвращает уведомление по id.

### `PATCH /notifications/{id}/read`

Помечает уведомление прочитанным.

### `DELETE /notifications/{id}`

Удаляет уведомление.

## Ошибки

Типовые статусы:

- `400` — бизнес-валидация или некорректное действие;
- `401` — нет токена или токен невалидный;
- `403` — роль или ownership не позволяют выполнить действие;
- `404` — сущность не найдена;
- `409` — конфликт, например повторный username;
- `422` — ошибка Pydantic-валидации;
- `429` — сработал rate limit;
- `500` — внутренняя ошибка приложения.

Для диагностики backend пишет структурированные логи с `request_id`.
